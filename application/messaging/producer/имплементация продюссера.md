# 3) Kafka Producer (конфиги, обёртка, DLQ)

**Нужны:**

* `application/src/main/java/ru/application/messaging/config/KafkaProducerConfiguration.java`
* `application/src/main/java/ru/application/messaging/MessagingProperties.java`
* `application/src/main/java/ru/application/messaging/producer/KafkaMessagePublisher.java`
* `application/src/main/java/ru/application/messaging/producer/DlqProducer.java`
* `application/src/main/java/ru/application/messaging/producer/DlqPublishRequest.java`
* `application/src/main/java/ru/application/messaging/KafkaHeaderUtils.java`
* `application/src/main/java/ru/application/messaging/KafkaMessageHeaders.java`

**Зачем:** мы будем публиковать в:

* `finam.md.quotes.v1`
* `finam.md.trades.v1`
* `finam.md.bars.v1`
* `finam.md.orderbook.v1`
* (опционально) `finam.tech.*`, `finam.trading.events.v1`, `finam.accounts.portfolio.v1`

и хотим использовать **Confluent Protobuf Serializer + Schema Registry** (ты уже настроил SR и совместимость). Надо убедиться, что в `KafkaProducerConfiguration` подтягивается:

* `key.serializer = org.apache.kafka.common.serialization.StringSerializer`
* `value.serializer = io.confluent.kafka.serializers.protobuf.KafkaProtobufSerializer`
* `schema.registry.url = http://127.0.0.1:8081` (или твой SR_URL)
* `auto.register.schemas=false` (мы уже регистрируем схему отдельно)
* `use.latest.version=true` (по желанию)
* `specific.protobuf.value.type` (если используем generated class `ru.domain.market.proto.MarketEvent`)

# 5) Сама typed-схема и сгенерированные классы

**Нужно одно из двух:**

* (a) сам `market_event.proto` в вашем `domain/src/main/proto/...` (или другом модуле) **и** `pom.xml` c `protobuf-maven-plugin`/`grpc-java` для генерации
* или
* (b) уже сгенерированный Java-класс `ru.domain.market.proto.MarketEvent` (+ остальные классы из файла: `Envelope`, `QuoteEvent`, `TradeEvent`, `OrderBookEvent`, `BarEvent`, и т.д.)

**Зачем:** продьюсер будет публиковать **typed Protobuf** (`MarketEvent`) в топики. Без сгенерированных классов мы не соберём payload.
